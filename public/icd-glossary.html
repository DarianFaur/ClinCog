How ICD-11 is built
The classification's own architecture — foundation, linearizations, and how codes are assembled
Foundation Component
The entire WHO-FIC universe: a single, multidimensional collection of every disease, disorder, injury, sign, symptom, and related entity WHO maintains, with each entity allowed to sit under more than one parent at once (e.g., a condition that is both an infection and a brain disease). Every linearization — including MMS, the one most people mean when they say "ICD-11" — is generated from this one shared foundation.
Linearization
A single-parent, tabular-list "cut" through the Foundation, built for a specific purpose — the kind of flat, printable hierarchy classic ICD volumes always were. MMS (Mortality and Morbidity Statistics) is the primary linearization: the main, general-purpose version used for coding and statistical reporting worldwide, and what the ICD-11 API in this course's CDDR guide searches by default. Other linearizations exist for primary care, dermatology, and other specialties.
Stem code / Precoordination
A stem code is a single, self-contained code that already bundles several pieces of clinical detail into one entity — e.g., a single code for "Adenocarcinoma of duodenum" that combines both the tissue type and the anatomical site. Building detail into one code like this is called precoordination.
Extension code / Postcoordination
Postcoordination is combining two or more codes into one cluster to describe a case more precisely than a single stem code allows — e.g., adding laterality or severity onto a diagnosis. Extension codes are the add-on codes used to do this; ICD-11 is the first ICD revision built to support this natively.
Grouping category, and "other specified" / "unspecified"
Some entries in a linearization exist only to organize other entries underneath them (chapters and blocks) and cannot themselves be assigned as a diagnosis — these are grouping categories. Within most groupings, "other specified" and "unspecified" residual categories catch presentations that don't fit any named category, or where information is incomplete.

The parts of a CDDR diagnostic write-up
Every disorder in the CDDR manual is described using this same set of headings
Essential (Required) Features
The features a clinician should expect to see in every case of the disorder — the closest thing CDDR has to "criteria," though written as clinical description rather than a rigid checklist.
In this course — the "Diagnostic criteria reproduced verbatim from World Health Organization…" text on each case's ICD-11 step is the Essential Features section for that disorder.
Additional Clinical Features
Features commonly seen in some, but not all, cases of the disorder — useful for recognition, but not required for the diagnosis to apply.
Boundary with Normality (Threshold)
Where CDDR draws the line between an ordinary human experience (sadness, worry, unusual belief) and the disorder — the severity, duration, or impairment threshold that has to be crossed before a diagnosis is appropriate.
Differential Diagnosis (Boundaries with Other Disorders and Conditions)
How to tell this disorder apart from others it's commonly confused with, including other mental disorders and relevant medical conditions — the section that matters most when two diagnoses both seem to fit.
Course Features
How the disorder typically unfolds over time — onset pattern, typical duration, episodic vs. persistent course, and common trajectories.
Developmental Presentations
How the disorder can look different at different ages — for instance, presentations more typical in children or adolescents versus adults.
Culture-Related Features
How cultural context can shape how symptoms are expressed, interpreted, or reported, and what a clinician should account for across different cultural settings.
Sex- and/or Gender-Related Features
Known differences in presentation, prevalence, or expression of the disorder associated with sex or gender.
